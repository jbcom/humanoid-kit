humanoid-kit is a pipeline from a recipe to a renderable, skin-weighted surface.
This page describes the pipeline as it exists in the repository, the invariants
that keep it honest, and, clearly separated at the end, what is planned. The
package is pre-release, so module boundaries may still move.

## One base mesh

Every figure is the hm08 base mesh from the MakeHuman asset set, released under
CC0 1.0: 19,158 vertices, 21,334 UV coordinates and 18,486 quads. The mesh is
split into face groups. The `body` group (13,378 quads) is the visible surface;
the rest are helper geometry for eyes, teeth, tongue, lashes, tights, hair and
skirt fit, and joint markers. There is no second mesh and no per-species
geometry. Variation comes only from morph targets applied to that one mesh, which
is why one skeleton and one set of skin weights cover every figure. The manifest
records `topology: "makehuman-hm08"` as the compatibility key for anything that
binds to this mesh.

## Packs and the binary format

The data ships as two CC0 packages, generated by `scripts/pack-makehuman.ts` and
read by `src/format/assetFormat.ts`. Binaries are little-endian; `body.bin` and
`attachments.bin` are 4-byte aligned, so typed-array views need no copies. All
lengths are in metres.

| Pack | Files | Contents |
| --- | --- | --- |
| `humanoid-kit-body` | `manifest.json`, `body.bin`, `targets.bin.gz`, `attachments.bin`, textures | Base mesh (positions, UVs, quad faces, UV indices), up to four skin bone indices and weights per vertex, the 163-bone skeleton with 326 joint vertex lists, 60 facial pose units, 936 sparse targets, 275 shape modifiers with MakeHuman's slider taxonomy, and the eyes, teeth and tongue |
| `humanoid-kit-adult-anatomy` | `manifest.json`, `targets.bin.gz` | 10 adult-only targets and 5 adult-only modifiers with their sliders |

A target is stored sparsely: the indices of the vertices it moves (`uint16`),
then their `int16` xyz deltas, plus a per-target scale in metres per step.
Evaluation multiplies a delta by `weight * scale`. For transfer, the targets
file stores each target's indices as ascending deltas and its x, y and z
deltas as separate planes, then gzips the whole file (`delta-planar-gzip`).
That takes the body targets from 18.8 MB to 5.5 MB; the loader decompresses
with the platform's `DecompressionStream` and decodes in one pass.

Each pack exports its file URLs (`bodyPack`, `adultAnatomyPack`) as literal
`new URL(..., import.meta.url)` expressions so bundlers emit the data files
without configuration. `loadHumanoidAssets({ body, adultAnatomy? })` accepts
those objects, or a string directory URL holding `manifest.json` and the
binaries (`PackLocation`). `parseHumanoidAssets` does the same from
already-fetched buffers.

The adult manifest records `topology` and `bodySha256`. The parser refuses it
unless both match the body pack it is combined with, so adult targets can never
be applied to a body they were not built for. Each pack's `data/PROVENANCE.md`
records the upstream commit, the CC0 evidence per source file and the SHA-256 of
every output. The packer's licence gate refuses any source file that does not
prove CC0 from its own content; see `NOTICE.md`.

## Recipe

```ts
interface Recipe {
  version: 1;
  macros: MacroValues;
  regionalMacros: Partial<Record<BodyRegion, Partial<Omit<MacroValues, "age">>>>;
  modifiers: Record<string, number>;
}
```

`macros` are MakeHuman's own variables: `gender`, `age` (years), `muscle`,
`weight`, `height`, `proportions`, `african`, `asian`, `caucasian`, `breastSize`
and `breastFirmness`. `modifiers` maps a shape modifier id to a value in
`[-1, 1]` (one-sided modifiers take `[0, 1]`); a missing id is 0. A recipe holds
no functions, no three.js objects and no references into the assets, so
`JSON.stringify` round-trips it.

### The macro model

MakeHuman's macro targets are combinatorial. A target's file name lists one
anchor per axis (`african-male-young`,
`universal-female-old-maxmuscle-minweight`), and its weight is the product of
its anchors' weights. Each axis is a linear interpolation between anchors:

- gender: female at 0, male at 1;
- age: baby (1 year), child (11), young (25) and old (90), piecewise linear, so
  every age from 1 to 90 is a blend of two anchors, clamped to that range;
- muscle and weight: three anchors each, 0, 0.5 and 1;
- height and proportions: one-sided from the base mesh, which is the average;
- the three ethnic anchors, normalised to sum to 1 (equal thirds if all are 0).

Upstream ships no file for some combinations because the base mesh already is
that shape; those are never named. Height and proportion targets are packed for
average muscle and weight only, and upstream has no baby proportion targets, so
proportions do not apply at the baby anchor.

### Regions

A trait is a set of morph weights; a region mask confines it to part of the body.
Regions are derived from the default skeleton's skin weights
(`src/makehuman/regions.ts`): `head`, `neck`, `chest`, `breastL`, `breastR`,
`arms`, `hands`, `abdomen`, `pelvis`, `legs` and `feet`. Skin weights already
fall off smoothly across joints, so summing the weights of each region's bones
gives soft masks. Six rounds of neighbour averaging widen the transitions,
and the masks are renormalised so they sum to 1 at every vertex. Vertices with no
skin weight fall to `chest`.

A regional override generalises MakeHuman's model. Each region evaluates the
macro model with the recipe's `macros` overlaid by that region's overrides. Any
macro except `age` can differ by region, for example a different gender anchor
for the face than for the hips, or a different breast size on each side. A target
whose weight is equal in every region is applied uniformly; the others get one
weight per region and are blended by the masks, so a trait set differently on the
face and the hips blends across the neck and waist instead of tearing.

## Age policy

`src/recipe/agePolicy.ts` supports all ages. The line is anatomy, not nudity:
under `ADULT_AGE` (18) a figure is MakeHuman's smooth doll form, which may be
shown with or without clothing.

Under 18:

- `breastSize` and `breastFirmness` must equal their defaults, in `macros` and in
  every regional override (the keys may not appear at all in a region);
- adult-only modifiers (ids starting `genitals/`, `pelvis/bulge` or
  `stomach/stomach-pregnant`) must be 0;
- a violation throws `AgePolicyError`. Values are rejected, never silently
  clamped, so a mistake cannot be hidden;
- the breast macro targets are never weighted (`macroTargetWeights`), although
  their files ship in the body pack;
- adult-only targets are not in the body pack at all; the adult anatomy pack's
  modifiers are adult-only, so a recipe under 18 that sets one is rejected.

The policy is enforced inside `recipeContributions`, so no caller can evaluate
an invalid recipe by skipping validation. `withAge(recipe, age)` returns a copy
at a new age; moving below 18 explicitly removes the adult-only values and leaves
the input untouched.

An adult-only modifier id that is not loaded (the adult pack is absent) fails
with `RecipeError`. Fine shape modifiers such as the `breast/*` and
`asym/asymm-breast-*` groups ship in the body pack and are not adult-only in the
code; the policy governs the controls listed above.

## Evaluation

`HumanoidModel` (`src/model/humanoidModel.ts`) is the framework-free pipeline for
one loaded body pack. It builds the region field and the render surface once and
evaluates recipes against them:

1. `recipeContributions` checks the age policy, evaluates the macro model per
   region and merges the results into contributions: uniform where the regions
   agree, per-region otherwise. Each modifier adds its `lo` or `hi` target by its
   value (clamped to `[-1, 1]`); a negative value on a one-sided modifier is a
   `RecipeError`.
2. `evaluateMorph` writes `base + Σ weight · delta` into the control mesh,
   applying per-region weights through the masks. An unknown target name throws
   `MorphError`, so a recipe never silently loses a trait.
3. `evaluateSurface` applies the subdivision stencil to the control positions,
   then computes smooth normals (area-weighted from each quad's diagonals,
   shared across UV seams).
4. The result is an `Evaluation`: positions, normals, `groundOffset` and the
   morphed `control` positions in the base topology (for joints, bindings and
   measurement).

The same recipe against the same assets always yields the same vertices; nothing
is random.

## Subdivision and the render surface

Smooth surfaces come from Catmull-Clark subdivision at 0, 1 or 2 levels
(`ModelOptions.subdivision`, default 1). The topology never changes, only vertex
positions do, so each refined vertex is a fixed linear combination of control
vertices. `src/subdiv/catmullClark.ts` builds that sparse matrix once as a
stencil and composes the levels into one; applying it is a sparse
matrix-vector product. Boundary edges use the crease rules, so open borders stay
put. UVs are subdivided linearly and face-varying, because MakeHuman's UV layout
has seams that smoothing would smear.

`buildSurfaceMesh` takes a subset of faces (the model uses the `body` group) and
produces the renderable form: the composed stencil, render vertices split at UV
seams, a triangle index buffer, UVs, and skin indices and weights interpolated
through the stencil and reduced to the top four per vertex. Static render data
(`SurfaceTopology`) is sent once; only positions and normals change per
evaluation.

## Worker

`HumanoidWorkerClient` is the main-thread handle to a Web Worker that owns one
`HumanoidModel`. The worker loads the packs, builds the model and replies with
the topology and the modifier ids. Evaluations are latest-wins: while one runs,
a newer request replaces any queued one, and the replaced request rejects with an
`AbortError`, so dragging a slider never builds a backlog. Results are
transferred, not copied. The client accepts an injected `Worker`; by default it
starts the built `dist/worker/index.js` next to it.

## Skeleton and facial pose data

The body pack carries the MakeHuman default skeleton (163 bones with parents,
head and tail joints and roll planes), the joint vertex lists, the skin weights
and 60 facial pose units (named frames of a BVH). Today the skin weights drive
the regions and are carried onto the render surface, and `jointPosition` returns
a joint's centroid over any set of positions. The runtime does not yet build a
three.js skeleton, pose a figure or play expressions, and `<Humanoid>` renders a
static mesh.

## Layers

| Folder | Role | React or DOM |
| --- | --- | --- |
| `src/format` | Pack types, parsing, loading, face groups, joint positions | no (uses `fetch`) |
| `src/morph` | Sparse morph evaluation with per-region weights | no |
| `src/makehuman` | Macro axes and target weights, regions, recipe to contributions | no |
| `src/recipe` | Recipe schema and defaults, the age policy | no |
| `src/subdiv` | Catmull-Clark stencils | no |
| `src/build` | Render surface: seams, indices, skin weights, normals | no |
| `src/model` | `HumanoidModel`, the evaluation pipeline | no |
| `src/worker` | Worker entry, protocol and `HumanoidWorkerClient` | no (Web Worker) |
| `src/react` | `HumanoidProvider`, `Humanoid` and hooks | yes |

`src/editor` does not exist yet. The pure folders are unit-tested in Node;
`src/react` and `src/worker` need a browser and are proven by Playwright against
the playground.

## Public demo

The GitHub Pages demo ships the body pack only. `pnpm check:pages` scans the
built output (`dist-playground` and `docs/dist` by default) and fails if it
contains an adult anatomy file (by SHA-256), the package name `humanoid-kit-adult-anatomy`,
or the name of any of its targets or modifiers.

## Invariants

1. One base mesh; no second skeleton or per-species geometry.
2. The age policy is enforced in evaluation and rejects, never clamps.
3. Adult-only data lives in its own package, bound to the exact body pack by
   `bodySha256`, and never in the public demo.
4. Regional traits are independent; none locks, clamps or rescales another.
5. The pure core imports no React, DOM or WebGL.
6. Subdivision is applied from precomputed stencils.
7. Data files are generated by the packer, not edited by hand, and the packer
   refuses any source that does not prove CC0.
8. Only CC0 asset data is used; no MakeHuman program code is included.

## Roadmap

Planned, in order. None of this is implemented yet.

1. **Doll form and editor shell.** `humanoid-kit/editor`: a contextual
   tap-to-edit creator over the recipe.
2. **Rig, poses and expressions.** A skeleton fitted to the morphed body, posing,
   and the facial pose units.
3. **Adult anatomy sculpt.** Sculpting on top of the adult anatomy pack, for
   figures aged 18 or over.
4. **Scalp hair.**
5. **Body and facial hair.**
6. **Anthro traits.**
7. **Clothing and surface layers.** Layers bound to the base mesh, including
   `.mhclo` assets with `delete_verts`; fur, scales and feathers as layers.
8. **Animation packs.** `humanoid-kit-animations`, and a separate
   `humanoid-kit-adult-animations` that refuses any participant under 18, plus
   spatial awareness for multi-person interactions.
